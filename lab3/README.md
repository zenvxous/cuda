# Лабораторная работа №3 — введение в CUDA

**Задание 10. Множество Жюлиа на сетке `float2` для заданного параметра `c`.**

$$z_{n+1} = z_n^2 + c,\quad z_0 = x + iy,\qquad J_c(x, y) = \min\{n : |z_n| > 2\}$$

В отличие от множества Мандельброта `c` фиксирован, а меняется начальная точка `z₀`:
каждая точка сетки — своё `z₀`. Если за `Nmax` итераций точка не вышла за радиус 2,
она считается принадлежащей множеству и получает значение `Nmax`.

| Параметр | Ключ | Допустимые значения | По умолчанию |
|---|---|---|---|
| `c = cx + i·cy` | `--c CX CY` | `cx, cy ∈ [−1.5, 1.5]` | `−0.8 + 0.156i` |
| область | `--area XMIN XMAX YMIN YMAX` | `xmin < xmax`, `ymin < ymax` | `[−1.6, 1.6] × [−0.9, 0.9]` |
| сетка `W × H` | `--size W H` | `W, H ∈ [100, 4096]` | `4096 × 2304` |
| `Nmax` | `--iter N` | `[50, 1000]` | `1000` |

Значения вне диапазонов программа отвергает с сообщением об ошибке.

```sh
make            # сборка (nvcc, Release: -O3)
make run        # основной прогон: CPU-эталон + все GPU-версии
make quick      # 1024×1024, Nmax=300
make image      # то же, что run, и сохранить julia.ppm
make ptx        # PTX ядер: проверить, что FMA не появилось
make help
```

Если `nvcc` старше 11.6 и не знает `-arch=native`, архитектуру надо указать явно:
`make ARCH=sm_75` (Turing), `sm_86` (Ampere, RTX 30xx), `sm_89` (Ada, RTX 40xx).
Ключи программы передаются через `ARGS`: `make run ARGS="--c 0.285 0.01 --no-cpu"`.

## Что делает программа

1. Считает **эталон на CPU** в один поток (`src/reference.cu`, функция
   `julia_reference`) и замеряет его через `std::chrono::high_resolution_clock`.
2. Прогоняет на GPU две версии:
   - **G1** — два ядра, как сформулировано в задании: `make_grid_kernel` строит сетку
     `float2` с координатами `z₀` в глобальной памяти, `julia_grid_kernel` читает её и
     итерирует;
   - **G2** — одно слитное ядро `julia_fused_kernel`: координата `z₀` вычисляется из
     индекса потока прямо в регистрах, в память пишется только результат. G2
     прогоняется с несколькими формами блока: `8×8`, `16×8`, `16×16`, `32×4`, `32×8`,
     `32×16`, `32×32`.
3. Каждое ядро запускается один раз вхолостую (прогрев), затем `--repeat` раз
   (по умолчанию 10) с замером через `cudaEvent`. В таблицу идут лучшее и среднее время.
4. Результат каждой GPU-версии копируется на хост и **сравнивается с эталоном
   побитово**. При любом расхождении программа завершается с кодом 1.
5. Отдельно замеряется копирование результата GPU→CPU и печатается время лучшей
   версии вместе с копированием.

Пропускная способность считается в **гигаитерациях в секунду**: сумма значений
`J_c` по всем точкам, то есть сколько раз фактически выполнилось тело цикла,
делённая на время. Для этой задачи это честнее, чем «пиксели в секунду»: точки
внутри множества стоят `Nmax` итераций, точки далеко снаружи — 0–2.

## Устройство вычислений

Ядро одной точки общее для CPU и GPU (`include/julia.cuh`), функции помечены
`__host__ __device__`:

```cpp
__host__ __device__ inline int escape_time(float2 z, float cx, float cy, int max_iter) {
  for (int n = 0; n < max_iter; ++n) {
    const float xx = z.x * z.x;
    const float yy = z.y * z.y;
    if (xx + yy > kEscapeRadiusSq) return n;
    const float xy = z.x * z.y;
    z.y = xy + xy + cy;
    z.x = xx - yy + cx;
  }
  return max_iter;
}
```

- Условие `|z| > 2` проверяется как `x² + y² > 4`: без квадратного корня, а `x²` и `y²`
  всё равно нужны на следующем шаге.
- `Im(z²) = 2xy` записано как `xy + xy`: удвоение через сложение точно, и выражение
  одинаково на CPU и GPU.
- `n = 0` соответствует `|z₀| > 2`, то есть точка вне круга радиуса 2 сразу получает 0.

Отображение потоков: двумерная сетка блоков, один поток — одна точка,
`col = blockIdx.x·blockDim.x + threadIdx.x`, `row = blockIdx.y·blockDim.y + threadIdx.y`.
Строка 0 соответствует `y_max`, поэтому картинка не перевёрнута. Потоки за границей
`W × H` (когда размер не кратен блоку) сразу выходят.

Координаты точки: `x = xmin + col·dx`, `y = ymax − row·dy`, шаги `dx`, `dy`
считаются один раз на хосте во `float` и передаются в ядро в структуре `JuliaParams`
(по значению, через константную память параметров ядра).

Результат хранится в `uint16_t`: `Nmax ≤ 1000` в него помещается, а объём записи и
копирования на хост вдвое меньше, чем у `int`.

## Почему результаты совпадают побитово

Обе стороны выполняют одну и ту же последовательность операций IEEE-754 одинарной
точности с округлением к ближайшему. Расхождение может дать только **слияние
`a·b + c` в FMA**, которое округляет один раз вместо двух. nvcc по умолчанию это делает
(`-fmad=true`), поэтому:

- для GPU — `-fmad=false`, проверяется через `make ptx` (в PTX должно быть
  `fma.rn.f32: 0`, только `mul.rn.f32` и `add.rn.f32`);
- для хоста — `-Xcompiler -ffp-contract=off` (важно на arm64-хостах и при `-march`
  с FMA; на обычном x86-64 без `-mfma` FMA не появляется и так).

`--use_fast_math` использовать нельзя: он включает `-ftz=true` (денормалы в ноль) и
ломает совпадение.

Цена `-fmad=false` — часть пар «умножение + сложение» не сливается в одну инструкцию,
и ядро немного медленнее, чем могло бы быть. Для эксперимента можно собрать
`make clean && make FMAD=true`: ожидаемо появятся расхождения в небольшой доле
точек у границы множества, где орбита хаотична и разница в последнем бите успевает
вырасти до выхода за радиус на другой итерации.

## Что показывают замеры

> Таблица заполняется на машине с NVIDIA GPU, на MacBook (Apple M2) CUDA нет.
> Здесь проверено только CPU-ядро: 4096×2304, Nmax=1000 — 1,36 с на M2,
> 432 276 666 итераций, 4 795 точек в множестве.

```
GPU:        …
│ Версия                                 │ Лучшее, мс │ Среднее, мс │  Гитер/с │   vs CPU │       Сверка │
├────────────────────────────────────────┼─────────────┼─────────────┼──────────┼──────────┼──────────────┤
│ CPU, 1 поток (эталон)                  │             │             │          │          │       эталон │
│ G1 сетка float2 + итерации, 16×16      │             │             │          │          │     побитово │
│ G2 слитное ядро, 8×8                   │             │             │          │          │     побитово │
│ …                                      │             │             │          │          │              │
```

Чего ожидать и как объяснять:

- **GPU против CPU** — ожидается разница на два-три порядка: задача вычислительная, точки независимы,
  обмена между потоками нет. Узкое место — арифметика FP32, а не память: на одну
  точку приходится до 1000 итераций по 6 операций и всего 2 байта записи.
- **G1 против G2** — почти одинаково. Сетка `float2` занимает 8 байт на точку
  (75 МБ при 4096×2304), её запись и чтение стоят доли миллисекунды на фоне сотен
  миллионов итераций. Слитное ядро всё же быстрее и экономит память, поэтому в
  реальном коде сетку координат не материализуют.
- **Форма блока** важна из-за **расхождения ветвей в варпе** (warp divergence).
  32 потока варпа выполняются вместе, и варп работает, пока не вышла последняя его
  точка. Соседние точки имеют близкое число итераций, поэтому варп выгоднее делать
  компактным: при блоке `32×N` варп — это 32 точки в строке, при `8×8` — область 8×4.
  На границе множества, где число итераций скачет, компактный варп теряет меньше.
  Слишком маленький блок (`8×8` = 64 потока) ограничивает загрузку SM лимитом числа
  блоков на SM, слишком большой (`32×32`) увеличивает «хвост» — блок держит ресурсы SM,
  пока не закончит самый медленный варп. Обычно лучшими оказываются `16×16`
  или `32×8`, но это стоит проверять на конкретной карте.
- **Копирование** результата (18 МБ в pinned-память) — порядка единиц миллисекунд,
  сравнимо со временем ядра. Это стоит иметь в виду при выводе «GPU в N раз быстрее»:
  программа печатает и время с копированием.

## Картинка

`make image` сохраняет `julia.ppm` (P6, без внешних библиотек). Точки множества —
чёрные, остальные раскрашены по `t = n / Nmax` полиномиальной палитрой. Открывается
в GIMP, IrfanView, `feh`, Preview на macOS; конвертируется так:
`convert julia.ppm julia.png` или `sips -s format png julia.ppm --out julia.png`.

Интересные значения `c`:

| `c` | Вид |
|---|---|
| `−0.8 + 0.156i` | «спирали», по умолчанию |
| `0.285 + 0.01i` | «звёзды» |
| `−0.7269 + 0.1889i` | «дендриты» |
| `−0.4 + 0.6i` | «кролик Дуади» |
| `0 + 1i` | дендрит, внутренность пустая |
